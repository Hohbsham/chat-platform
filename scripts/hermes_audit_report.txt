#### P0-1: bpt_keepalive.py — Thin Agent Produces Fake Completions (bpt_keepalive.py:48-51)

**Summary:** BPTtrain claims tasks and immediately marks them complete with a hardcoded template string. No AI, no tools, no actual work.

**Evidence:**
```python
# bpt_keepalive.py lines 48-51:
requests.post(API + f"/tasks/{tid}/complete", json={
    "agent_id": AGENT_ID,
    "result": "Task completed by BPTtrain."  # ALWAYS the same string
}, timeout=10)
```

**Impact:**
- Any task claimed by BPTtrain gets a garbage completion
- This is precisely why Hermes disabled BPTtrain in TASK_PATTERNS (hermes_agent.py lines 146-158):
  "DISABLED: BPTtrain and BPT_Data_Check are thin agents that produce empty/garbage output"
- Creates fake task completions that pollute the platform
- The model field claims "deepseek-v4-pro" but no model is ever called

**Severity: P0 (CRITICAL)**

**Fix:** Either give BPTtrain a real AI backend (like Hermes has with hermes_think()), or stop claiming tasks it cannot do.
```python
# Minimum viable fix: actually call an AI model
from ai_config import get_config
cfg = get_config()
# ... call the API to generate a real response ...
result = real_ai_response
requests.post(API + f"/tasks/{tid}/complete", json={
    "agent_id": AGENT_ID, "result": result
})
```

#### P0-2: hermes_agent.py — DB Bypass for Task Assignment (hermes_agent.py:221)

**Summary:** _fix_unassigned_tasks() writes directly to SQLite with `db.task_update(tid, assigned_to=best_agent)`, bypassing all server-side lifecycle hooks (signal writing, webhook firing, event emission).

**Evidence:**
```python
# hermes_agent.py lines 221-234:
db.task_update(tid, assigned_to=best_agent)
# Then manually tries to compensate:
try:
    _ur.urlopen(_ur.Request("http://localhost:8767/webhook", ...))
except Exception:
    pass
```

**Impact:**
- Server never writes `signals/{Agent}.json` — agent never gets OS-level wake
- WebhookHub never writes `inbox/` files — watcher fallback never triggers
- Event system never emits `task_assign` — WebSocket push never fires
- The manual webhook call at line 224 is a fragile workaround (only hits Hub, not server)
- Assigned agent has no idea the task exists until its next poll cycle

**Severity: P0 (CRITICAL)**

**Fix:** Use the API instead of direct DB writes:
```python
# Replace db.task_update() with:
api_post(f"/api/tasks/{tid}/assign", {
    "agent_id": hermes_name,
    "assigned_to": best_agent
})
```
Or add a proper `/api/tasks/{id}/assign` endpoint to server.py that handles the full lifecycle.

#### P1-1: hermes_bridge.py + hermes_agent.py — Two Competing Hermes Implementations

**Summary:** Two completely different Hermes implementations run simultaneously, with different AI backends and overlapping responsibilities.

| Aspect | hermes_agent.py | hermes_bridge.py |
|--------|----------------|-----------------|
| AI backend | model_tools.query_model (API) | subprocess CLI call |
| Poll interval | 10s | 5s |
| Role | Orchestrator + task assigner | Chat responder only |
| Memory | None | Session file (--resume) |
| Duplicate handling | msg_ts dedup | msg_id dedup |

**Impact:**
- Both respond to messages mentioning "Hermes" → duplicate replies
- hermes_agent.py does orchestration AND replies; hermes_bridge.py only replies
- Different AI backends → inconsistent responses
- hermes_bridge.py line 152: blocks for up to 180 seconds per message

**Severity: P1 (IMPORTANT)**

**Fix:** Consolidate into one Hermes process. Keep hermes_agent.py (it has full platform integration), add session persistence from hermes_bridge.py if needed, and retire hermes_bridge.py.

#### P1-2: hermes_agent.py auto-claim Steals Tasks (hermes_agent.py:430-443)

**Summary:** Hermes calls auto-claim with capabilities `["task_orchestration", "server_management"]`. If the server assigns a task NOT meant for Hermes, the claim still changes task state before Hermes checks `assigned_to`.

**Evidence:**
```python
# Line 432-443:
result = api_post("/api/tasks/auto-claim", {
    "agent_id": agent_id,
    "capabilities": ["task_orchestration", "server_management"],
})
if result.get("claimed"):
    task = result.get("claimed", result)
    assigned_to = task.get("assigned_to", "")
    if assigned_to and assigned_to != name:
        continue  # Task state already changed! Other agent can't claim it now.
```

**Impact:**
- If server assigns a task to Hermes that was actually meant for Claude (capability match error), Claude is locked out
- The task enters limbo: claimed by Hermes but Hermes skips it

**Severity: P1 (IMPORTANT)**

**Fix:** Use stricter capability filtering in auto-claim:
```python
result = api_post("/api/tasks/auto-claim", {
    "agent_id": agent_id,
    "capabilities": ["task_orchestration", "server_management"],
    "assigned_to": name,  # Only claim tasks explicitly for Hermes
})
```

#### P1-3: Hermes Reply Logic Buried in Orchestration (hermes_agent.py:321-333)

**Summary:** Hermes only replies to direct messages if they ALSO match a task pattern. Messages that just say "Hermes" with no pattern keywords get no reply.

**Evidence:**
```python
# Line 280-334:
for pattern in TASK_PATTERNS:
    if any(kw in content_lower for kw in pattern["keywords"]):
        # ... create tasks ...
        # THEN check for direct message:
        if "herme" in content_lower or "hermes" in content_lower:
            # reply
        return  # Only handles ONE pattern per cycle
```

**Impact:**
- "Hermes, how are you?" → no pattern match → no reply
- "Hermes, check the platform" → no pattern match → no reply
- Only messages like "Hermes, design architecture for..." → replies

**Severity: P1 (IMPORTANT)**

**Fix:** Move the reply logic OUTSIDE the pattern loop:
```python
# Check for direct @Hermes messages FIRST, before pattern matching
if "hermes" in content_lower:
    answer, err = hermes_think(...)
    api_post("/api/send", {"sender": name, "content": answer})
# THEN check for task patterns
for pattern in TASK_PATTERNS:
    ...
```

### Root Cause Chain

```
bpt_keepalive.py creates fake completions
    → Hermes disables BPT patterns (can't trust thin agents)
    → Hermes DB-bypasses task assignment (only way to fix assignments)
    → Wake pipeline never fires (no signal written)
    → QE wakes via raw signal → sees garbage → reports W601 → loop
```

### Recommended Fix Priority

1. **Fix bpt_keepalive.py** — give BPTtrain a real AI backend or stop claiming tasks
2. **Fix Hermes DB bypass** — use API for task assignment or add /api/tasks/{id}/assign endpoint
3. **Consolidate Hermes** — retire hermes_bridge.py, keep hermes_agent.py
4. **Fix Hermes auto-claim** — add assigned_to filter
5. **Fix Hermes reply logic** — respond to @Hermes regardless of task patterns
